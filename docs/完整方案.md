# 主参赛方案：《我的机器人分身》· WorldStage Physical Twin

**版本：2026-09-29 12:10 UTC。** 本文按用户最新要求取代此前的“简单可交互 3D 微世界”主方案。三套独立备选仍保留：羽毛球 Real2Sim、四足少数据 Sim2Sim/Sim2Real、以及此处的 3D 世界方案。当前主赛题选择第三套，但它的价值中心已变为**面向机器人训练的可生成物理世界和差异证据**；游戏、动漫、IP、教育是同一世界构建能力的应用出口。

## 1. 价值命题

现有仿真工具擅长在**已构建**的模型和场景里计算动力学；制作规模大、语义丰富、持续变化、与真实世界相关的训练场景仍需大量人工，并且往往缺少跨引擎/实物的误差账本。WorldStage 让用户用文字、图片或现实采集定义任务，在一个大场景中持续加入可见、可碰撞、带物理参数的新资产，再把**同一场景**送入浏览器预览、MuJoCo、Isaac Sim 与真实数据比较。

核心产出不是一段“会动的 3D 视频”，而是可复用的 **World Episode**：世界坐标/单位、几何与视觉资产、碰撞代理、质量/摩擦/恢复系数/重力、机器人模型与传感器、任务/交互、初态/随机种子、轨迹、接触事件、跨引擎差异、素材/模型来源与 SHA。它可用于生成反例场景、选择真实采集片段、评估机器人策略的迁移差距。

**必须明确**：MuJoCo 本身已有重力、碰撞和关节动力学。本项目不会宣称浏览器 Rapier 比 MuJoCo 更真实；它先补强开放世界内容生成、语义任务、视觉条件变化与场景覆盖，再通过 Isaac Sim/PhysX、MuJoCo 和真实测量揭示每个引擎何处不一致。

## 2. 用户现场体验

1. 用户在 80 × 80 米世界输入“增加雨后低摩擦斜坡、一排可滚动球、一棵遮挡深度相机的树”。
2. **NVIDIA Nemotron** 把意图转成受限的世界对象和任务 JSON。几何/材质/碰撞体异步生成，物体无需重启场景即可出现。模型失败时明确标为模板，绝不写成 NVIDIA 推理。
3. 导入真实 S10 URDF，显示关节树、质量、碰撞几何和资源 SHA。用户在大场景里给目标点、看路径、记录碰撞与失败阶段。
4. 导出场景 JSON、MuJoCo XML、后续 USD/Isaac Sim 场景和回放日志；固定初态/种子在两种物理引擎复测，并选需要真实机器人数据校准的误差最大的片段。
5. 对内容领域：相同引擎可把“机器人任务”替换成游戏机制、动漫/IP 叙事和教学实验，但必须保留各领域独有的评估指标。

## 3. NVIDIA 核心模型与 GX10 方案

### 模型职责

- **核心必需：NVIDIA Nemotron；首选 Nemotron 3 Nano Omni**。Omni 接收文字/图片/视频条件，可承担空间语义解析、对象约束和任务规划。NVIDIA 的 [DGX Spark 官方 Nemotron playbook](https://build.nvidia.com/playbooks/nemotron/instructions-nano) 给出单台 GB10 + vLLM 的 OpenAI-compatible 服务，示例模型名 `nemotron_3_nano_omni`、端口 8000。此路线尚未在租用 GX10 实测。
- **已实测：NVIDIA Nemotron 3 Nano 4B GGUF**。NVIDIA 官方[模型卡](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-4B-GGUF)提供 `llama.cpp` OpenAI-compatible 路线。韩国租用实例 `53340625`（GB10/aarch64）上已下载 NVIDIA 官方仓库 Q4_K_M 权重，以 CUDA 后端启动本地服务；`/v1/models` 返回 `nemotron-3-nano-4b-gguf`，WorldStage 成功生成台阶和低摩擦斜坡，页面出现 `NVIDIA Nemotron` 来源。模型只标注支持英语，中文输入虽在三次实例中成功，仍需固定提示词集检验结构化输出质量。详见[GX10 运行回执](./results/instance-53340625/worldstage/gx10-nemotron-receipt.json)。
- **可选视觉生成：NVIDIA Sana**。它可以异步给新资产生成外观/材质参考图；几何仍需程序化建模、图生 3D 模型或已有资产库，并由可验证碰撞体承载物理。Sana 是 NVIDIA Research 的图像模型，具体 GX10 部署和速度需实测。[NVIDIA Research Sana 源码](https://github.com/NVlabs/Sana)。
- **可选真实世界视频增强：NVIDIA Cosmos**。只用于视觉条件和视频数据增强，不能把生成视频当作真实接触力、摩擦系数或成功标签。[NVIDIA Cosmos 官方教学](https://docs.nvidia.com/learning/physical-ai/sim-to-real-so-101/latest/14-strategy3-cosmos.html)把它定位于场景/数据变体。当前 [Cosmos 前提条件](https://docs.nvidia.com/cosmos/latest/prerequisites.html)对部分 Predict/Transfer 分支写明 Linux x86-64，故不能默认为 GX10 aarch64 可直接运行；可先用支持的 Reason2 或独立 RTX 服务验证。
- **物理/机器人：Isaac Sim/PhysX + MuJoCo**。NVIDIA 的 [Isaac Sim 当前要求](https://docs.isaacsim.omniverse.nvidia.com/latest/installation/requirements.html)列出 DGX Spark aarch64、DGX OS 7 和受测驱动，并注明 DGX Spark 上 cuRobo/cuMotion 限制。租用 GX10 的系统/驱动/容器权限需核实；如果不符合，改用独立兼容 RTX 主机跑 Isaac Sim，GX10 保持 Nemotron 核心推理。

### 设备排程与完成判定

GX10 同时跑 Nemotron、3D 生成和 Isaac Sim 可能争抢 128 GB 统一内存。先独占启动 Nemotron 完成身份/推理/延迟回执；再按剩余显存决定是否串行启动 Isaac Sim。不要一边跑 Workshop 的 Qwen/TAO，一边默认再起 Nemotron/Isaac，除非确认 GPU/CPU/内存预算。

Nemotron 证明需要：`/v1/models` 返回、进程对应权重目录/版本、模型权重 SHA、陌生提示词的结构化输出、`provenance.mode=nvidia_nemotron`、时延和设备身份。本次回执覆盖这些层次：权重 SHA `be5d9a65…c5a0b5ef2`、NVIDIA 模型仓库修订 `ba223d14…`、llama.cpp 源修订 `86ea01d0…`、实例/进程/CUDA 动态库及三次 WorldStage 真实生成。`check_nemotron.py` 单独只验证 API 层，不能把服务别名本身当作身份；完整设备回执见上方文件。

## 5. 真实物理与 Sim2Sim 的方法

### 统一合同

`world_episode.json` 应包含 `source_hashes`、`coordinate_system=z_up`、`units=m_kg_s`、`gravity=[0,0,-9.81]`、每个对象的视觉资产/碰撞资产/质量/摩擦/恢复系数、机器人 URDF/MJCF 身份、控制接口、传感器标定、初态、种子与目标。用一个转换器同时输出 MJCF 和 USD；任何一端单位、旋转、摩擦字段缺失都记为转换失败。

### 三层物理证据

1. **浏览器 Rapier**：实时创作和碰撞预览，S10 是运动学代理；可帮用户选择有价值的障碍布局。
2. **MuJoCo + Isaac Sim/PhysX**：同一 S10、同一场景、同一控制器和初态，比较任务完成、接触和传感器差异。只有实际两边运行，才叫完整 Sim2Sim。
3. **真实机器人**：授权采集带时间戳的状态/动作/外部测量，选择最能区分模型假设的少量片段做 Real2Sim 参数校准，再独立审查 Sim2Real。失败与安全边界必须保留。

### 已完成的一项配对探针

项目内 `examples/physical-world/` 有 80×80 米世界、低/中台阶、高台、斜坡、低/高摩擦材料区和 2 kg 自由落体箱。`studio/verify_physics.py` 把官方 S10 URDF 的碰撞/惯量派生模型和同一世界合成，在 MuJoCo 3.14.0 下编译并步进 1.2 s，记录 60 帧无控制关节状态与接触数：26 body、36 geom、30 qpos、28 qvel，重力 `-9.81 m/s²`，接触发生。`studio/compare_engines.mjs` 对同一重力箱用 Rapier 再跑 1.2 s：接触前 3 个采样点平均绝对高度差 **0.00772 m**，1.2 s 沉降高度差 **0.00001 m**。这仅证明基本刚体场景传递与差异测量路径可用；S10 未受控，关节级步态、双引擎机器人对照和真机数据均 `NOT_RUN`。

## 6. 比赛演示与后续价值验证

### 三小时内提交的真实垂直切片

- 在 `/lab.html` 给 80×80 米场景实时增加树/水晶/建筑/坡/球/台阶；产生结构化几何、材质、质量和摩擦参数，动态物体受重力影响。
- 导入项目现有 S10 原始 URDF（20 link/19 joint/27 collider，源 SHA 留存）；机器人在浏览器用运动学代理接受 W/A/S/D、目标点和自动探索，并导出**带来源标签**的轨迹。
- 用一次按钮导出 `scenario.json` 与 MuJoCo 世界 XML；独立脚本已验证含 S10 的世界可运行，并给出配对重力箱差异文件。
- GX10 的 Nemotron 推理已取得主证据：NVIDIA 官方权重在 GB10 上运行，WorldStage 生成了台阶/斜坡并留存原始模型候选、字段校验和耗时。模板路径保留为离线回退；模型输出的质量/摩擦等参数仍是未测量假设。

### 决赛价值门槛

| 指标 | 目标或检验方式 |
|---|---|
| 场景丰富度 | 至少 3 类地形、10 类对象、动态/静态、不同摩擦/照明；不能只展示一个岛屿 |
| 新物体生成 | 输入新意图 → 受限规划 → 几何/材质/碰撞进入现有场景；记录端到端 P50/P95 时延、失败率与人工修订量 |
| 物理可用率 | 生成 episode 在 MuJoCo 与 Isaac 都能导入并运行的比例；单位/穿模/碰撞代理质量 |
| Sim2Sim 差异 | 同源场景的位姿、接触时刻、峰值冲量、任务成功率及首败阶段；不以单一箱体探针泛化 |
| 真实价值 | 少量真实采样相对于随机采样，能否更快降低预测误差、提高未见场景成功率；同预算对照和置信区间 |
| 内容应用 | 游戏首个可玩关卡时间、IP 世界一致性、教育学习前后测；与机器人指标分别报告 |

**90 秒演示**：先展示 GX10 Nemotron 身份与一次陌生对象生成回执；在 80×80 米场景生成并投放新障碍；把 S10 URDF 模型驶向目标点并呈现碰撞/轨迹；导出 JSON+MJCF；展示同一个 2 kg 物体在 Rapier/MuJoCo 的配对曲线与 S10 MuJoCo 编译/步进回执；最后说明 Isaac/真实机器人尚待验证的边界。

## 8. 作品叙事升级：《我的机器人分身》

序章由“主人，欢迎穿越到您的机器人分身”引导。用户先在 S10 轮腿与 TurtleBot3 Burger 轮式两个官方开源 URDF 中选择载体，再抵达记忆锚点、让 NVIDIA Nemotron 召唤新物体、运行场景准入报告；四片线索完成后可走实验室、现实残影或数字分身三条真相路线。谜题把物理能力和来源证据变成剧情规则，结局提出下一步验证，不伪装成真实机器人经历。新增 `avatar-casting`、`memory-puzzle-director` 和 `worldgen-visual-intake` 三个 Skill。

经用户授权的 Hyper3D WorldGen 已从项目参考图导出七件分离 GLB，页面实际加载 7/7。输入图像和原 ZIP 的 SHA、逐件 GLB SHA 及变换矩阵见 `demo-3d/public/worldgen/manifest.json`，原始 ZIP 在 `worldgen-assets/`。这七个 GLB 在浏览器作为视觉层，并由原始顶点和三角面创建七个 Rapier 静态网格碰撞体；仓库另加入工业试验仓围合视觉和可互动谜题。运行时采用一源单位等于一演示米的设计假设，米制尺寸、接触行为和摩擦没有实测校准；MJCF 仍使用简化代理，准入报告列出七项跨引擎碰撞形状不一致并阻止机器人训练。因此不能据此说 WorldGen 原始网格已可供机器人训练。图片生成可运动机器人分身仍需网格、骨架/关节、惯量、碰撞体和驱动限制，并在 MuJoCo/Isaac 复核，当前 `NOT_RUN`。
