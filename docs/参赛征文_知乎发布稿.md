# 我们给机器人造了一个会继续生长的世界，也给每个结果留了证据

最初想做 WorldStage 时，我们画了一个很直接的画面：在屏幕里放进一台四足机器人，输入一句“前面加一块湿滑的台阶”，世界就长出一个新障碍，机器人走过去，我们顺手拿到训练数据。

真正动手后，最先遇到的问题不是怎样把台阶画出来，而是：这个台阶有多重？摩擦系数从哪里来？网页里走过去的机器人，能代表真机吗？如果这几个问题没有答案，漂亮的三维画面很容易让人误以为实验已经成立。

所以我们把作品改成了一个更诚实的流程：先生成世界，再标明它凭什么生成；让机器人代理探索，留下轨迹；把场景交给物理引擎；最后给结果盖上清楚的状态章。

## 一句话变成一个可测试场景

打开 WorldStage 的机器人世界实验室，会看到一个 80 × 80 米的场景。你可以放入球、斜坡、石柱，也可以输入自己的新物体。物体不只有名字和颜色，还带着尺寸、材质、质量和摩擦。Rapier 负责浏览器里的重力与碰撞，场景可以导出为 JSON 和 MuJoCo XML。

NVIDIA Nemotron 有一个已经跑通的工作：把一句「做一段低摩擦斜坡」变成有类型、尺寸和物理字段的受约束 JSON。WorldStage 检查字段，再把物体放进试验仓。比赛窗口里，我们在租用的 ASUS Ascent GX10 上实际运行了 NVIDIA Nemotron 3 Nano 4B GGUF，生成过低摩擦斜坡和石台阶；回执记录设备、CUDA 后端、模型权重哈希、请求、候选内容和字段接纳情况。固定的斜坡、球、石柱三题严格通过 3/3，模板回退 0。这只能证明这三道生成题的结果。

断开模型后，页面会退回确定性模板，同时把「模板」写进生成来源。演示时看见一个物体，并不能自动推断它由 Nemotron 生成。我们实际用的是 4B 文本模型，架构是混合 Mamba2/Transformer；这次没有运行 MoE 版本，也没有把 Omni 或看图能力接进来。[NVIDIA 模型卡](https://huggingface.co/nvidia/NVIDIA-Nemotron-3-Nano-4B-GGUF)列出了所用量化版本和架构。

同一套世界构建能力还有一个轻一点的入口：输入“漂浮在云海上的夜光森林”，六项 Skill 会处理主题、规划场景、构建 3D、设计交互、组织故事、校验导出。它让游戏、教育和创意 IP 有了可探索的原型，但我们把比赛主线放在机器人场景上，因为那里更需要证据。

## 真正的机器人，有限的网页代理

我们引入了 DEEPRobotics S10 的真实 URDF，保留原始文件、BSD 许可和 SHA-256。文件里有 20 个连杆、19 个关节和 27 个碰撞体。网页可以据此显示机器人结构，代理可以在场景中移动并记录接触。

这里最容易说过头。网页中的移动采用运动学碰撞代理，不是 S10 的关节级动力学，更不是真机走过同一路线。我们把这个限制写在页面、报告和导出说明里。代理轨迹可以帮助挑选场景，却不能直接变成可部署的动作标签。

Nemotron 的第二个工作接在这段探索之后。网页每隔约 0.1 秒记录人的方向意图、代理位置、接触和谜题事件；程序先算出停滞窗口、碰撞热点、目标点和场景准入问题，再将结构化摘要交给 Nemotron。模型接口只允许它从已有证据中选风险代码，提出一个候选机器人任务和下一项测量。玩家点过的目标点会另行形成带来源与 SHA 的仿真任务候选；模型的建议留在审核报告，不会改写任务事实。当前这条链路的离线正反例是 8/8，通过的是采集与规则；**Nemotron 行为审核的实时模型评测还没跑，状态为 `NOT_RUN`**。

为了让导出的世界至少能跨出浏览器，我们用 MuJoCo 3.14.0 编译了 S10 与世界组合场景，完成 1.2 秒的无控制步进，并记录了 60 帧关节状态和接触数。我们还用一个 2 千克的自由落体箱做 Rapier/MuJoCo 配对，接触前平均高度差是 0.00772 米。这个数字只属于这个单刚体探针。它不能替 S10 的上坡、落脚和关节接触背书。

## 为什么做场景准入

物理世界里的一个对象如果有质量、摩擦和碰撞体，看起来就像“可训练”。实际情况是，这些值往往只是模型给出的猜测。我们加了场景准入 Skill：结构是否完整、MuJoCo XML 能否导出、哪些物理参数还没测、网页代理与机器人模型哪里不一致，都放进报告。Nemotron 可以建议先查哪种风险，却不能把训练状态改成通过。当前状态写得很明确：结构通过，机器人训练 `BLOCKED`；NVIDIA SimReady 认证也未运行。

这个门槛改变了我们看 Demo 的方式。生成得快，是一个产品能力；知道何时不能把结果交给训练系统，也是一个产品能力。前者让场景不断增加，后者让团队知道应该先测哪一块。

## 这次黑客松留下了什么

短时间里，我们交付了可运行的本地网页、20 个可独立检查的 Skill、S10 和 TurtleBot3 URDF 导入、七件 WorldGen 导出资产、物体生成与来源记录、玩家行为审核与仿真任务候选、场景/轨迹导出、MuJoCo 冒烟测试、单刚体跨引擎对照，以及 GX10 上 Nemotron 4B 的实际推理回执。20 个 Skill 的指定离线案例是 20 PASS；这个数字不包含 Nemotron 行为审核的实时质量。源码和项目报告都放在 GitHub，评委可以按 README 自己启动并复核。

也有几件事没有做完：Nemotron 行为审核的实时评测与 Omni 都没有运行；WorldGen 源网格没有米制标定，MJCF 仍用简化碰撞体；Isaac Sim 还没有用同一场景复核；S10 没有进行关节控制实验；没有采集真实机器人数据，因此我们没有 sim2real 收益数字。这些是下一阶段的实验，不会被网页画面补成「已完成」。

如果继续做，我们会先固定场景版本和初始状态，让 Rapier、MuJoCo、Isaac Sim 对同一物体给出可比较的轨迹与接触时刻，再用授权的真实数据校准关键参数。到那时，WorldStage 才可能从一个会生长的世界，走向机器人团队愿意反复使用的实验场。
